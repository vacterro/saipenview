[P1] [CORE-001] saipenview/ui/static/app.js / protocol source-editor Save path
EVIDENCE: The frontend constructs project protocol-file paths with Windows separators, e.g. `detail.root + "\\.saipen\\" + fileName` and `root + "\\.saipen\\STATE.md`. The Save handler later classifies a protocol file only with `currentFilePath.indexOf(".saipen/") !== -1`. For a real Windows path such as `V:\proj\.saipen\STATE.md`, that expression is false, so `write_file_text` receives only `[path, content]` rather than `[path, content, currentFileEditVersion]`. A Node reproduction using that Windows path produced `isProtocol: false` and argument count 2. Backend `Api.write_file_text` independently recognizes the path as a protocol file and rejects an existing protocol-file write when `edit_version` is absent. Existing backend tests supply the token directly and therefore do not exercise this frontend/backend separator mismatch.
DEFECT: Protocol-file detection in the primary source-editor Save flow assumes POSIX `/` separators while the same frontend deliberately creates Windows `\` paths. On the intended Windows runtime, editing an existing `.saipen` file can therefore omit its required CAS edit token and make a legitimate Save fail.
REPAIR: Make frontend protocol-path classification separator-independent and ensure an existing protocol document always forwards its `currentFileEditVersion`. Use one canonical helper, for example separator normalization before testing for `/.saipen/`, rather than duplicating path heuristics. Preserve the backend requirement that stale or missing CAS tokens cannot overwrite an existing protocol file.
VERIFY: Add a frontend regression covering both `C:\project\.saipen\STATE.md` and `C:/project/.saipen/STATE.md`; after opening a response containing an `edit_version`, Save must call `write_file_text` with exactly three arguments and the same token. Keep/add backend coverage proving a matching token succeeds and stale/missing tokens remain rejected.

[P1] [CORE-002] saipenview/runtime.py / ProcessManager.kill, _exit_monitor, _finalize
EVIDENCE: The launch path documents the dedicated exit monitor as the owner of process finalization, and `_exit_monitor` waits for `proc.wait()` before invoking `_finalize`. `kill()`, however, sets `_kill_intent`, sets `ap.status = "killed"`, attempts terminate/wait then kill/wait, tolerates a second wait timeout, and still calls `_finalize(ap, requested_status="killed")`. `_finalize` sets `ap._finalized = True` before death is established, suppresses a timed `process.wait()` failure, accepts `process.returncode is None`, then records `finished_at`, publishes terminal status, calls `sessions.finish`, and emits `agent.finished`. A deterministic fake process whose `wait()` always raised `TimeoutExpired` and whose `returncode` remained `None` reproduced `status="killed"`, non-null `finished_at`, `_finalized=True`, and an `agent.finished` event despite the process never being proven dead.
DEFECT: Terminal lifecycle state is committed before process death is established. A slow or uncooperative child can still be alive and producing output after the run has been marked finished; the session transcript may already be closed, later output can be discarded, `agent.finished` is false, and `_finalized=True` prevents the real exit monitor from repairing the terminal record.
REPAIR: Make proven process exit the prerequisite for finalization. Prefer the existing design intent in which the exit monitor owns `_finalize`: `kill()` should record kill intent and perform signalling/wait escalation without independently committing terminal state when death is unproven. In `_finalize`, do not set `_finalized`, `finished_at`, terminal status, close the session, or emit `agent.finished` until `returncode` proves exit. Drain/join the output reader and finish the transcript before exposing the terminal state/event. If the kill waits time out, retain a nonterminal state and let a reap/exit path finalize exactly once after death.
VERIFY: Add a fake-process regression where terminate/kill waits time out and `returncode` stays `None`: assert no terminal status, no `sessions.finish`, no `agent.finished`, and `_finalized` remains false. Then make the fake process exit and run the exit path: assert exactly one finalization/event, correct killed status, and complete transcript. Retain a normal real-process kill regression.
