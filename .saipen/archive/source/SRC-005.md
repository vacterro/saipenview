[P0] [CORE-001] saipenview/saio.py::engine / _load_codec_from / _load_freshness_from

EVIDENCE:
- engine() resolves a home and checks the process-global _ENGINE_CACHE at saipenview/saio.py:153-184, then mutates process-global sys.path and imports globally named modules at 186-199, only publishing ownership into _ENGINE_CACHE afterward at 202.
- _load_codec_from() performs the same unsynchronized check -> sys.path mutation -> import sequence at 132-150.
- _load_freshness_from() repeats it at 578-607.
- No lock serializes the home-ownership check, sys.path mutation, sys.modules import, or cache publication.
- Home-key normalization is inconsistent: engine() uses str(home).lower() at line 164 while _load_codec_from() and _load_freshness_from() use raw str(home) at lines 137 and 588.
- Deterministic two-thread probe against the real loader synchronized both workers after each had inserted a different temporary SAIPEN home but before either first import. Result:
  SAIO_RACE_RESULTS {'B': ('B', 'B'), 'A': ('B', 'B')}
  SAIO_RACE_CACHE_KEYS contained both HomeA and HomeB keys.
  Both callers therefore passed the "one home per process" guard, project A received project B's module objects, and both homes were subsequently represented as cached.
- This is exactly the state the comments at lines 156-183 claim must be impossible.

DEFECT:
The canonical-writer authority invariant is check-then-act rather than atomic. Concurrent first use can admit two distinct SAIPEN homes before either publishes cache ownership. Python's name-based sys.modules then selects one home's modules for both callers, after which contaminated modules can be cached under both project identities. A project can consequently execute canonical mutation logic from a different protocol home/version. This is a fundamental writer-authority correctness failure with data-corruption potential.

REPAIR:
- Introduce one process-wide re-entrant SAIO loader lock covering the complete home resolution/ownership check, sys.path/import transaction and cache publication for engine, codec and freshness loading.
- Maintain one normalized canonical home identity through a shared helper; do not mix raw and lowercase cache keys.
- Prefer an explicit process owner such as _ENGINE_HOME_KEY rather than inferring ownership from the first arbitrary dict key.
- Before accepting imported modules, verify their __file__/package origin is beneath the selected canonical home; fail closed if a globally preloaded saipen_engine/freshness module originates elsewhere.
- Keep the existing SaioUnavailable multi-home refusal contract.

VERIFY:
- Re-run the two-home barrier test. Exactly one home may initialize; the other caller must receive SaioUnavailable and _ENGINE_CACHE must contain only the authoritative home identity.
- Run simultaneous engine(), codec and freshness first-use combinations, not just engine/engine.
- Preload saipen_engine from a foreign tools directory and verify the loader refuses rather than silently adopting it.
- Add a mixed-case/same-home test proving every loader resolves to one cache/ownership identity.
- Run canonical write/claim/transition tests concurrently on Windows and confirm no cross-home module identity is possible.
