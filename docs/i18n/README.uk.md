## 🧬 Протокол SAIPEN

SAIPENVIEW — це супутник для проєктів, які використовують **Протокол SAIPEN** — фреймворк конечних автоматів, який проводить ШІ-агентів через роботу над проєктом по визначених фазах:

```
INIT → PLAN → SCOUT → BUILD → REVIEW → VERIFY → SHIP → DONE
                 ↓              ↓
            HUNT / CLEAN    VALIDATE
```

`ADD`, `MARKHUNT`, `TRANSLATE`, `PREPARE` також існують - повний словник і таблиця переходів у `saipenview/protocol.py` (`BLOCKED` досяжний з більшості фаз).
Кожен проєкт SAIPEN зберігає свій стан у трьох канонічних файлах:

| Файл | Призначення |
|---|---|
| `.saipen/STATE.md` | Машинозчитувані метадані — фаза, завдання, наступна дія, блокер |
| `.saipen/BOARD.md` | Дошка тікетів — розділи DOING / TODO / DONE / BLOCKED |
| `.saipen/LOG.md` | Хронологічний журнал подій — кожна команда та її результат |

**Суб-агенти SubSaipen** (`saiwiki`, `saihunt`, `saitranslate`) розміщуються у `.saipen/extensions/subs/` і спілкуються через `kitchen/OUTBOX.md` — вбудовану шину повідомлень між агентами протоколу. SAIPENVIEW знаходить їх усі та відображає на єдиній панелі.

### Відповідність стандарту (Conformance)

Відображення того, що проєкт *повідомляє* — це лише половина справи. Проєкт може чудово виглядати у списку — фаза, завдання, наступна дія — але при цьому перебувати у стані, який протокол відхиляє, і поки ви не запустите `tools/validate.py` вручну, неможливо відрізнити одне від іншого.

Кожен рядок має значок вердикту, а панель деталей містить список помилок:

| Вердикт | Значення |
|---|---|
| `OK` | У власних файлах `.saipen/` цього проєкту не виявлено проблем |
| `N WARNS` | Допустимо, але є відхилення — застарілий чекпоінт, нестандартне дієслово LOG |
| `N FAILS` | Стан, який протокол відхиляє: `WAIT:` без категорії, прапорець, який суперечит своєму розділу, `needs:`, що вказує на неіснуючий тікет, UTF-16 `STATE.md`, який не може прочитати жоден інший інструмент SAIPEN |

Кожне зауваження називає правило, файл і рядок, а також пункт стандарту, з якого воно походить, щоб його можна було знайти, а не приймати на віру.

Це **друга думка, а не заміна** для `tools/validate.py`. Вона перевіряє лише те, що можна визначити з власних файлів проєкту, і оцінює за копією словників протоколу — тому версія SAIPEN, з якої її було зчитано, виводиться під кожним вердиктом. Переглядачу дозволено відставати від протоколу. Йому не дозволено відставати мовчки.

> 💡 *Назва "SAIPENVIEW" говорить сама за себе — вона забезпечує **перегляд** (view) кожного проєкту **SAIPEN** на вашому комп'ютері.*

## ⚙️ Конфігурація

Конфігурація є портативною — вона зберігається поруч із застосунком, а не в `%APPDATA%`:

```
saipenview/_data/config.json
```

Основні значення за замовчуванням (скорочено - повний словник `DEFAULTS` у `saipenview/config.py`):

```json
{
  "hotkeys":          ["ctrl+alt+x", "alt+f15"],
  "snap_hotkey":      ["ctrl+q"],
  "zoom_level":       1.0,
  "font_family":      "Verdana_m1",
  "scan_roots":       null,
  "rescan_interval":  300,
  "scan_depth":       6,
  "scan_delay_ms":    10,
  "exclude_dirs":     [],
  "auto_scan":        true,
  "show_on_launch":   true,
  "always_on_top":    true,
  "frameless":        true,
  "flash_changes":    true,
  "locale":           "en",
  "default_engine":   "claude-code",
  "file_viewer_default": "source",
  "layout_swap":      false
}
```

Встановіть `scan_roots: null` для автоматичного виявлення всіх локальних дисків.  
Встановіть список шляхів (наприклад, `["V:\\", "D:\\projects"]`), щоб обмежити сканування.  
`default_engine` / `engine_overrides` / `agent_output_buffer_size` керують Agent Engine (див. Можливості).  
Усі налаштування також можна змінити через модальне вікно **Налаштування** у застосунку.

## 🏗️ Архітектура

```
saipenview/
├── app.py              Вхідне з'єднання - трей, гаряча клавіша, вікно, api, захист від дублів
├── api.py              Міст pywebview для JS (66 публічних методів)
├── scanner.py          Обхід дисків + цикл фонового пересканування
├── parser.py           Парсинг STATE.md / BOARD.md / LOG.md
├── textio.py           Єдиний зчитувач для кожного файлу .saipen/ — BOM, UTF-16, cp1251
├── protocol.py         Закриті словники протоколу + BASELINE_VERSION
├── conformance.py      Оцінка проєкту на відповідність цим словникам
├── config.py           Завантаження/збереження налаштувань (атомарний запис)
├── tray.py             Іконка системного трею pystray + меню
├── hotkey.py           Реєстрація глобальних гарячих клавіш (бібліотека keyboard)
├── autostart.py        Управління автозапуском у реєстрі Windows
├── zone_picker.py      Оверлей прилипання до кута Ctrl+Q (tkinter)
├── events.py           Внутрішньопроцесна шина подій (EventBus)
├── guard.py            Блокування єдиного екземпляра + передача запиту показу
├── git_diff.py         Diff / commit / revert робочого дерева для дій агентів
├── runtime.py          Agent Engine - менеджер процесів запущених агентів
├── watcher.py          Watchdog-спостерігач за файлами .saipen/
├── engines/            Agent Engine - підтримувані CLI-рушії (claude-code, codex,
│                       aider, gemini, cline, goose, agy, generic_cli)
├── ui/
│   ├── window.py       Вікно pywebview — показати/сховати/переключити/прив'язати
│   └── static/
│       ├── index.html
│       ├── style.css   Вінтажна темно-золота тема Win95
│       └── app.js      Логіка фронтенду (~3300 рядків)
├── assets/
│   └── tray_icon.png
├── screenshots/        Скріншоти для README
└── _data/              Конфігурація часу виконання + кеш (в gitignore)
```

### Принципи дизайну

- **Єдиний процес** — без фонового IPC, без окремого сервера; один процес Python містить як вікно WebView2, так і цикл сканування у `ThreadPoolExecutor`
- **Атомарний запис** — кожен запис файлу використовує тимчасовий файл + `os.replace`; збій ніколи не пошкодить конфігурацію чи кеш
- **Безпека читання застарілих даних** — 5-секундне опитування UI викликає `refresh_known()` (перечитує лише файли `.saipen/`, без обходу директорій). Зміни в STATE.md з'являються протягом декількох секунд без запуску повного сканування диска
- **Без CSS-переходів** — усі візуальні ефекти (спалах, теплова індикація, наведення) є перерахунками `hexBlend` на JavaScript, що суворо відповідає обмеженню вінтажної теми щодо відсутності анімацій
- **Вінтажна тема** — темно-коричневі поверхні, золотий текст/акценти, об'ємні 3D-рамки, відсутність згладжування (zero anti-aliasing), шрифт Verdana_m1

### Вимоги
